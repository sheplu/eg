# __PROJECT_NAME__

Express 5 TypeScript API generated by `eg`.

## Requirements

- Node.js 20.11+
- npm

## Getting started

```sh
npm install
npm run dev
```

The API listens on `http://localhost:3000` by default.

## Scripts

```sh
npm run dev              # Start the API in watch mode
npm run build            # Compile TypeScript to dist/
npm start                # Run the compiled server
npm test                 # Run all native Node.js tests
npm run test:unit        # Run unit tests
npm run test:integration # Run integration tests
npm run test:e2e         # Run e2e tests
npm run test:coverage    # Run tests with native Node.js coverage thresholds
npm run typecheck        # Type-check without emitting files
npm run lint             # Lint with oxlint
```

## Configuration

Environment variables:

| Name | Default | Description |
| --- | --- | --- |
| `NODE_ENV` | `development` | `development`, `test`, or `production` |
| `HOST` | `0.0.0.0` | Server bind host |
| `PORT` | `3000` | Server port |
| `LOG_LEVEL` | `info` (`silent` in tests) | Pino log level |
| `CORS_ORIGIN` | `*` | CORS origin, or `false` to disable browser origins |

## Validation

Input validation uses AJV and JSON Schema.

- Add schemas in `src/schemas/`.
- Attach schemas to routes with `validate({ body, params, query })`.
- Validation failures return a consistent `VALIDATION_ERROR` response.

Example:

```ts
router.post('/users', validate({ body: createUserSchema }), controller.createUser);
```

## Testing

Tests use the native Node.js test runner with `tsx` for TypeScript loading.

- Unit tests exercise isolated services.
- Integration tests start the Express app on an ephemeral local port.
- E2E tests call the API over real HTTP.

Run all tests:

```sh
npm test
```

Run tests with native Node.js coverage thresholds:

```sh
npm run test:coverage
```

Coverage thresholds are enforced by the Node.js test runner: 95% lines, 95% functions, and 95% branches.

## Error responses

Errors use this shape:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Request validation failed",
    "details": [],
    "requestId": "..."
  }
}
```

Every response receives an `x-request-id` header. You can pass your own request ID with the same header.
